# Architecture as a Complementarity Signal

**Do Vision Transformers and Vision State-Space Models fail differently, and can that
disagreement be used?**

This repository contains the complete, reproducible experiment suite behind the paper
*"Architecture as a Complementarity Signal: Error Overlap, Disagreement and Explanation
Divergence between a Vision Transformer and a Vision State-Space Model"*.

Everything is CPU-friendly to *read* and GPU-assisted to *run*: one Colab T4 session
(≈ 2 h) is enough to reproduce the head-line tables.

---

## What is being tested

| # | Question | Experiment |
|---|----------|------------|
| Q1 | Does combining ViT + VMamba predictions improve accuracy, and when does it fail? | Proba/logit averaging + weight sweeps over all model pairs |
| Q2 | Does *disagreement* between ViT and VMamba identify incorrect predictions better than *confidence*? | Selective prediction: AURC, AUROC, Risk@coverage (+ DeLong / bootstrap) |
| Q3 | Do perturbations that fool one architecture fool the other? | FGSM & PGD transfer matrices across architectures |
| Q4 | When both models are right, do they look at the same regions? When they disagree, do explanations explain it? | Occlusion sensitivity on a 7×7 grid; map correlation / SSIM; inner-vs-border mass |
| Q5 | Which architecture handles unfamiliar distributions better, and are failures complementary? | ImageNet-A / -R / -Sketch / -V2 / background-only |

The **priorities** (per the brief): *error overlap, corruption sensitivity, background
dependency, error predictability*.

## Results (filled in from `results/`)

See `results/REPORT.md` for the auto-generated table set; every number in the paper is
produced by a script that writes a file here. Nothing is hand-typed.

## Layout

```
src/
  models.py            ViT (timm) + VMamba (VSSM) with identical preprocessing
  vmamba_pt.py         VSSM loader using the official code + pure-torch selective scan
  datasets.py          ImageNet-val / -A / -R / -Sketch / -V2 / background-only loaders
  corruption.py        Hendrycks-style corruptions (15 × 5) made deterministic
  inference.py         single-pass feature + logit extraction
  metrics.py           selective prediction, error overlap, AURC/AUROC, calibration
  ensemble.py          pair-wise ensemble + weight sweep
  explanations.py      occlusion sensitivity, map agreement, inner-vs-border mass
  adversarial.py       FGSM / PGD + transfer matrix
  probes.py            "will the other model be wrong?" linear probes
  stats.py             bootstrap CIs, DeLong test, permutation, Holm–Bonferroni
  plots.py             every paper figure is regenerated by this
  run_pipeline.py      CLI: python -m src.run_pipeline --step <name>
run_step.py            Colab entry-point (fetch repo, run a step, save artifacts)
notebooks/run.ipynb    upload this to Colab (GPU) and press "Run all"
paper/                 IEEE LaTeX source (IEEEtran, 6 pages, two columns)
```

## Reproduce on Colab (T4)

1. Upload `notebooks/run.ipynb` to <https://colab.research.google.com>, set *Runtime →
   Change runtime type → T4 GPU*, and *Run all*.
2. Set the Kaggle credentials when the notebook asks (the notebook reads
   `/content/kaggle.json` if present).
3. The notebook runs the pipeline, writes `results/*.json` and `figures/*.png`, and
   zips them to `/content/arch-complementarity.zip` for download.

## Reproduce locally

```bash
pip install -r requirements.txt
export KAGGLE_USERNAME=... KAGGLE_KEY=...
python -m src.run_pipeline --step prepare          # download val, A, R, Sketch, Bg
python -m src.run_pipeline --step inference        # models x datasets -> npz
python -m src.run_pipeline --step combine          # ensembles + selective prediction
python -m src.run_pipeline --step explanations     # occlusion maps
python -m src.run_pipeline --step adversarial      # transfer matrices
python -m src.run_pipeline --step probes           # error predictability
python -m src.run_pipeline --step analyse          # tables + figures + REPORT.md
```

## Integrity notes

- All checkpoints are public pretrained ImageNet-1K models, used **without fine-tuning**.
- Models are compared with **matched preprocessing** (`timm.data.resolve_model_data_config`
  is reused for every model so the crop/resize is identical).
- Accuracies in `results/checkpoints.json` are measured on ImageNet-val and must match
  each model's published number within 0.5 pp; a model failing this check is *not used*.
- Every experiment writes raw per-image logits so all tables can be recomputed.
- Failed / OOM runs are logged to `results/run_log.jsonl` and never silently dropped.
